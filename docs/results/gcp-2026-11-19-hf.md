# GAMST-HF run, GCP 2026-11-19: baseline with two change detectors

**Status:** measured. This is a baseline for "GAMST with two change-detector plugins". It is not evidence that GAMST works, and it is not a SOTA claim.

## Setup

- **Data:** 119 seeded StreamArena episodes. These are real YouTube videos with human labels; see `docs/GAMST_HF_DATASET.md`.
- **Gate:** Qwen3-VL-8B-Instruct-FP8 (`9cdc631`). An episode is admitted only if this model fails both the 1 FPS control and the first+last-frame control. 88 episodes were admitted.
- **Judge:** Gemini 3.1 Pro on Vertex, using the StreamArena judge prompts.
- **Pro timing:** the official window, −0.5 s to +2.0 s around the event.
- **Hardware:** one L4 (g2-standard-8, asia-northeast3-b).
- **Artifacts:**
  - `data/campaigns/gcp-2026-11-19-hf/`
  - `gs://gamst-bench-datasets-optimum-zone/gamst-hf/2026-11-19/results/`
  - `minsing-jin/gamst-hf-bench` (private, under `results/`)

## Arms

| Arm | What runs |
|---|---|
| `qwen_small` | Qwen2.5-VL-3B, 2 FPS, video only |
| `streamingvlm` | mit-han-lab/StreamingVLM `7ac1cef`, served as a VLM on vLLM with online FP8 and upstream decoding defaults |
| `gemini_live` | `gemini-live-2.5-flash-native-audio`. 1 FPS video plus 16 kHz audio in real time, with sliding-window context compression |
| `strong` | Gemini 3.1 Pro on the full AV clip (4 FPS for ≤30 s windows, otherwise 2 FPS) |
| `strong_videoonly` | Same as `strong` on the audio-stripped clip. T3 items only (AV ablation) |
| `gamst` | Inputs: StreamingVLM native per-second state, causal motion-energy and audio-onset plugins, and GAMST `SemanticStateFusion` and `SemanticStateChain`. These are sent as MCP context to Gemini 3.1 Pro with ≤6 signal-peak keyframes. Alert calls follow a frozen app rule. |
| `gamst_nomedia` | Same as `gamst`, with 0 keyframes: the state chain only |

Only 3 T3 items passed the AV check (strong right with audio, wrong without it). On those 3 items, `strong` scored 3/3 and `gemini_live` 1/3; every other arm scored 0/3.

StreamingVLM native state ran on all 88 episodes with 0 errors. The median realtime factor was 0.896.

## Reading the result

1. `strong` is best on every family. GAMST is 15/88 against strong's 33/88, so **GAMST did not match strong-model quality**.
2. **GAMST did not save tokens either**: 2.0 M prompt tokens against 1.07 M. Three reasons:
   - Alert polling was triggered by every motion burst and every StreamingVLM state change.
   - The state-chain JSON was large.
   - The two plugins only report "something changed", so they carry no semantics for these questions.
3. **Raw StreamingVLM is not usable as a QA model.** This checkpoint is trained for live commentary. Its per-second state is mostly empty or reads like invented speech, so the "video semantic state" fed into GAMST was weak.
4. `gamst` beats `gamst_nomedia` (15 vs 8). The keyframes picked at signal peaks carried most of the value.
5. 39 `gemini_live` rows are still empty replies even after the protocol fixes. The native-audio Live model often stays silent on text questions after a long AV stream. That row is a lower bound for Live, not its ceiling.
6. StreamArena questions are mostly semantic and labelled at whole-second resolution. They do not isolate what GAMST is meant to add: counting, sub-second timing, rhythm, rule-based probability and memory.

## Run incidents (fixed before the counted pass)

- **Gate model OOM:** Qwen3-VL-8B BF16 ran out of memory on 128-image prompts. The gate was moved to the official FP8 checkpoint, and the failed pass is kept in `failed_try1/`.
- **Truncated sources:** 9 source videos were left truncated by an interrupted fetch. They were re-fetched, their clips rebuilt, and their gate rows redone.
- **Live format silence:** the Live model stays silent when asked for the bracketed `ANSWER | EVIDENCE_T` format. It was given a spoken version of the same request.
- **Live context limit:** Live answers came back empty once the ~32 k-token context filled. Fixed by turning on sliding-window compression.
- **Plugin import:** the modality plugin was missing `import json` and was rerun.

## Decision

This benchmark was run before GAMST's capabilities were defined. That was the wrong order. The capabilities are now defined in the GAMST repository, in `docs/capabilities.md`: count, probability cloud, moment capture and physics, rhythm, and memory, plus modality combinations. Each one is verified on small real data before any new benchmark is run.
