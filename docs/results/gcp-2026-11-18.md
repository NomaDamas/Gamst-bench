Full held-out runs, stable rate limits, independent audit and session-level uncertainty are still required.

## FastBench C/D postmortem

The low C/D scores are **not valid evidence that GAMST itself fails FastBench**. The measured C/D tracks were extension experiments with a protocol mismatch:

1. A-baseline preserved FastBench's accumulated native visual dialogue. C/D replaced that with a thumbnail-difference trigger, one selected evidence frame and a compact text context. GAMST temporal memory stores timestamps, change scores and semantic summaries; it cannot reconstruct pixels the VLM never received.
2. ProactiveFrame focus windows re-send earlier frames at higher FPS. The adapter skipped already-observed timestamps to preserve GAMST causal ordering. That fixed a real timestamp invariant but removed part of FastBench's expected focus evidence.
3. The adapter simplified FastBench's `Silent`/`Focus_Start`/`Focus_End` lifecycle and native timed-response semantics. The native scorer therefore did not receive an equivalent front-end contract.
4. The cheap thumbnail signal detects visual change, not object identity, action, OCR, state, or audio-video meaning. It is insufficient by itself for FastBench's semantic and forward/backward questions.

Therefore the C/D scores are valid only as **adapter-failure/dev observations**, not as a GAMST quality score. The benchmark does test visual temporal QA and timing, but not GAMST's full multimodal-context thesis (audio/tactile/physical fusion, long retention, revision or recovery).

### Corrective experiment

- **Policy-only:** keep the exact native FastBench frame/message transport and scorer; let GAMST decide only call/no-call. This isolates policy quality.
- **Context ablation:** compare native context, selected frames + native dialogue, and selected frames + compact GAMST context under the same evidence budget.
- **GAMST-native evaluation:** use the six-suite A–E protocol for multimodal claims: video, audio/ASR, tactile/physical signals, timestamped evidence, cutoff-filtered context, revision, retention and recovery. Do not substitute FastBench for this evaluation.
